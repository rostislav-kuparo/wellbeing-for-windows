# Wellbeing — экранное время для Windows

Wellbeing считает, сколько времени вы проводите в каждой программе, и **жёстко закрывает** программу, когда дневной лимит исчерпан. Интерфейс — веб-страница в отдельном окне (WebView2), тёмная и светлая тема, всё по-русски.

- Учитывается только время, когда окно программы **активно** и вы что-то делаете. Если ввода нет дольше 2 минут, время останавливается. Исключение — полноэкранные окна: видео и игры.
- День начинается в **04:00**, поэтому засиживание после полуночи считается тем же днём.
- Лимит задаётся в минутах на программу или на **группу программ** («Игры» = несколько .exe). Можно указать отдельное значение для выходных.
- **Разрешённое время**: например, игры только с 18:00 до 22:00 (можно и через полночь, 20:00–01:00). Вне этого времени программа закрывается. Окно можно сочетать с лимитом минут или выбрать «без лимита минут».
- За 10, 5 и 1 минуту до конца лимита приходит уведомление. Когда лимит исчерпан, программа закрывается, а повторный запуск сразу прерывается.
- **Уменьшение и новые лимиты действуют сразу, увеличение и удаление — со следующего дня.** Так в порыве не получится «дать себе ещё полчасика».

## Как это устроено

```
┌──────────────── сессия пользователя ────────────────┐      ┌──────────── сессия 0 (SYSTEM) ─────────────┐
│ Wellbeing.Agent.exe (трей)                          │      │ Wellbeing.Service.exe (служба WellbeingSvc)│
│  • раз в секунду: активное окно + бездействие ──────┼─────►│  • учёт времени, лимиты, SQLite            │
│  • уведомления  ◄───────────────────────────────────┼──────┤  • блокировка (WMI Win32_ProcessStartTrace)│
│  • окно WebView2 с интерфейсом  ◄── HTTP + SSE ─────┼──────┤  • REST API + веб-интерфейс на 127.0.0.1    │
└─────────────────────────────────────────────────────┘      │  • перезапуск агента, если он пропал       │
                                                             └────────────────────────────────────────────┘
```

Служба работает от SYSTEM в сессии 0 и не видит рабочий стол, поэтому активное окно определяет агент. Если агент не отвечает дольше 10 секунд, служба его перезапускает. Пока агента нет, время идёт **всем запущенным программам с лимитом** — иначе завершение агента давало бы бесплатное время.

Подробности (схема БД, API, алгоритмы) — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Требования

- Windows 10 (1903+) или Windows 11, x64.
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) — в Windows 11 уже есть.
- Для сборки: .NET 10 SDK (`winget install --id Microsoft.DotNet.SDK.10 -e`) и Node.js 20+.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File deploy\build.ps1
```

Скрипт собирает веб-интерфейс, прогоняет тесты и публикует службу и агента как self-contained single-file для win-x64. Результат кладётся в `dist\`: два exe по ~50 МБ (рантайм .NET внутри), несколько нативных dll рядом, папка `wwwroot`, а также `install.ps1` и `uninstall.ps1`. Ключ `-SkipTests` пропускает тесты.

## Установка

Из обычного PowerShell. Скрипт сам запросит права администратора (окно UAC) и продолжит установку в новом окне:

```powershell
powershell -ExecutionPolicy Bypass -File dist\install.ps1
```

Что делает скрипт:

| Шаг | Подробности |
|---|---|
| Копирует файлы | в `C:\Program Files\Wellbeing`. Пользователи могут только читать, менять — SYSTEM и администраторы. |
| Создаёт папку данных | `C:\ProgramData\Wellbeing` (БД, логи, токен). Доступ только у SYSTEM и администраторов. Исключение — `agent.json` с токеном API: его могут читать вошедшие пользователи. |
| Регистрирует службу | `WellbeingSvc`, запуск автоматический. При сбое служба перезапускается через 5 с, 5 с и 30 с. |
| Автозапуск агента | `HKLM\…\Run`, плюс ярлык «Wellbeing» в меню «Пуск». |
| Запускает службу | и ждёт ответа `/api/health`. Агента служба запустит сама в течение ~10 секунд. |

Повторный запуск `install.ps1` обновляет программу, данные сохраняются. Порт по умолчанию — `47613`, задаётся параметром `-Port`.

## ⚠️ Повседневный аккаунт должен быть без прав администратора

Программа защищает от импульсивных решений, а не от администратора компьютера. Администратор может остановить службу, удалить программу, поменять права — и это правильно: `uninstall.ps1` — ваш аварийный выход.

Поэтому для настоящей защиты:

1. Создайте **отдельную учётную запись администратора** с надёжным паролем, который вы не помните наизусть. Например, запишите его на бумагу и уберите подальше.
   *Параметры → Учётные записи → Другие пользователи → Добавить пользователя*, затем *Изменить тип учётной записи → Администратор*.
2. Сделайте **повседневную учётную запись стандартной**: *Изменить тип учётной записи → Стандартный пользователь*.
   Или из PowerShell от администратора: `net localgroup Администраторы <ваш_логин> /delete` (в английской Windows группа называется `Administrators`).
3. Работайте под стандартной учётной записью. Когда понадобятся права администратора, Windows спросит пароль второй учётной записи.

Под стандартной учётной записью нельзя остановить службу (`sc stop WellbeingSvc` → «Отказано в доступе»), изменить файлы в Program Files и ProgramData, удалить программу или поменять автозапуск в HKLM.

## Удаление

Из PowerShell. Скрипт сам запросит права администратора (UAC); под стандартной учётной записью Windows спросит пароль администратора:

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Program Files\Wellbeing\uninstall.ps1"
```

Скрипт отключает автоперезапуск, останавливает службу и агентов, удаляет службу, автозапуск, ярлык, файлы программы, данные (`-KeepData` их оставит) и папки WebView2 в профилях. Каждый шаг выполняется независимо, поэтому скрипт работает и после неполной установки, и когда служба не отвечает. PowerShell, Диспетчер задач и всё из `C:\Windows` никогда не блокируются, так что аварийный выход всегда доступен.

Если скрипта под рукой нет, всё можно сделать вручную, от администратора:

```powershell
sc.exe config WellbeingSvc start= disabled; sc.exe stop WellbeingSvc
taskkill /F /IM Wellbeing.Service.exe; taskkill /F /IM Wellbeing.Agent.exe
sc.exe delete WellbeingSvc
Remove-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run -Name Wellbeing
Remove-Item "C:\Program Files\Wellbeing", "C:\ProgramData\Wellbeing" -Recurse -Force
```

## Как проверить, что всё работает

1. **Служба запущена и перезапускается при сбое.**
   ```powershell
   Get-Service WellbeingSvc          # Status: Running
   sc.exe qfailure WellbeingSvc      # RESTART -- Delay = 5000 …
   ```
2. **Агент в трее.** В трее есть значок Wellbeing, по клику открывается окно. На странице «Сегодня» в строке «Сейчас:» видна программа, в которой вы работаете. Через пару минут без мыши и клавиатуры там появится «пауза — нет активности».
3. **Блокировка.** Удобно проверять на Калькуляторе Windows 11 (`CalculatorApp.exe` — приложение из Store, его можно ограничить):
   - «Лимиты» → «Добавить лимит» → выберите калькулятор (`calculatorapp.exe`; если его нет в списке, сначала запустите его на пару секунд) → 1 минута.
   - Поработайте в калькуляторе минуту: придёт предупреждение «Осталось 1 мин», затем калькулятор закроется с уведомлением «Лимит на сегодня исчерпан».
   - Запустите его снова — он закроется сразу.
4. **Правило «с завтра».** Увеличьте этот лимит до 30 минут. Ответ будет «Вступит в силу завтра в 04:00», в списке появится запланированное изменение, а калькулятор по-прежнему будет закрываться. Удалите лимит, чтобы не мешал: он перестанет действовать завтра.
5. **Перезапуск агента.** Завершите `Wellbeing.Agent.exe` в Диспетчере задач. Значок вернётся через 10–20 секунд, в «Настройки → Журнал» появятся записи «Агент не отвечает…» и «Агент запущен».
6. **Защита от остановки** — под стандартной учётной записью:
   ```powershell
   sc.exe stop WellbeingSvc          # [SC] OpenService: ошибка 5 — Отказано в доступе
   ```
7. **Состояние.** В «Настройки → Состояние» должно быть «служба Windows», «Агент: на связи», «Блокировка запусков: мгновенно (WMI)».

Логи службы лежат в `C:\ProgramData\Wellbeing\logs\` (читать — от администратора), лог агента — в `%LOCALAPPDATA%\Wellbeing\agent.log`.

## Правила учёта и лимитов

| Что | Как |
|---|---|
| Что считается | Время, когда окно программы активно. Бездействие дольше порога (по умолчанию 2 мин) не считается, кроме полноэкранных окон. Заблокированный экран и сон не считаются. |
| Начало дня | 04:00 (настраивается). Дни отсчитываются по этому времени, а не по полуночи. |
| Группа | Время всех программ группы складывается в один лимит. Программа может входить в несколько лимитов — блокирует любой исчерпанный. |
| Разрешённое время | Вне окна (например, 18:00–22:00) программа закрывается и не запускается. Внутри окна действует лимит минут, если он задан. Предупреждения за 10/5/1 мин приходят и перед концом окна. Окно берётся по логическому дню: в 01:00 субботы действует окно пятницы. |
| Сразу | Новый лимит, уменьшение минут, новое или более узкое разрешённое время, добавление программы в группу, увеличение порога бездействия, переименование. |
| Со следующего дня | Увеличение минут, расширение или отключение разрешённого времени, удаление лимита, исключение программы из группы, уменьшение порога бездействия, смена времени начала дня. |
| Смешанное изменение | Например, будни 60 → 30 и выходные 60 → 120: будни ужесточаются сразу, выходные ослабляются с завтра. Сдвиг окна 18–22 → 20–23: сегодня действует пересечение 20–22, с завтра — 20–23. |
| Нельзя ограничить | Всё из `C:\Windows`, Проводник, системные процессы, PowerShell, Диспетчер задач, WebView2, сам Wellbeing. Если программа с таким именем есть в Windows (например, `notepad.exe`), её тоже нельзя ограничить. |
| Без агента | Время идёт всем запущенным программам с лимитом в активной сессии, пока агент не вернётся. |

Лимиты и статистика общие для всего компьютера: они действуют для любого пользователя, вошедшего за физический экран.

## Разработка

```powershell
# служба в консоли: данные в %LOCALAPPDATA%\Wellbeing.Dev, порт 47614, без прав администратора
dotnet run --project src\Wellbeing.Service

# агент, подключённый к консольной службе
dotnet run --project src\Wellbeing.Agent -- --dev --show

# интерфейс с горячей перезагрузкой: http://localhost:5173 (прокси сам подставит токен)
cd web; npm install; npm run dev

# тесты
dotnet test
```

В консольном режиме служба не запускает агента сама. Без прав администратора WMI-события о запуске процессов недоступны, поэтому вместо них работает проверка раз в 5 секунд.

```
src/Wellbeing.Core      логика без WinAPI: учёт, логический день, политика лимитов, белый список (+ xUnit-тесты)
src/Wellbeing.Win32     WinAPI за интерфейсами Core: процессы, сессии, WMI, CreateProcessAsUser, иконки
src/Wellbeing.Service   служба: Kestrel на 127.0.0.1, SQLite, трекер, блокировщик, сторож агента, API, SSE
src/Wellbeing.Agent     трей-агент: heartbeat, уведомления, окно WebView2
web/                    React + Vite + TypeScript + Tailwind + Recharts → src/Wellbeing.Service/wwwroot
deploy/                 build.ps1, install.ps1, uninstall.ps1, make-icon.ps1
tests/                  Wellbeing.Core.Tests, Wellbeing.Service.Tests
```

## Известные ограничения

Программа рассчитана на честное использование самим собой. Обойти её можно, но это требует осознанных усилий — на это она и рассчитана.

- **Администратор может всё**: остановить службу, удалить программу, изменить права. Отсюда требование к повседневному аккаунту.
- **Переименование или копирование exe.** Лимиты привязаны к имени файла: `game.exe`, скопированный как `notgame.exe`, считается другой программой.
- **Программы из `C:\Windows` ограничить нельзя**: Блокнот, Paint, `mstsc` и т. п. Это плата за гарантию «настройки не сломают Windows».
- **Сайты в браузере.** Сейчас можно ограничить только браузер целиком. Правила по заголовку окна (например, «YouTube» в `chrome.exe`) заложены в архитектуру, но ещё не реализованы.
- **Агент работает от имени пользователя.** Технически продвинутый пользователь может подменить его данные (например, внедрившись в процесс). Защиты от этого нет — это осознанное решение.
- **Античиты уровня ядра** у некоторых онлайн-игр могут не дать завершить процесс игры.
- **Безопасный режим.** Служба там не запускается.
- **Режим «Не беспокоить»** скрывает уведомления-предупреждения. Блокировка при этом работает как обычно.
- **Удалённый рабочий стол (RDP)** не отслеживается — учитывается только сессия за физическим экраном.
- **Часовой пояс.** Обычный пользователь может сменить часовой пояс и этим сдвинуть начало дня на несколько часов. Перевод часов назад ничего не даёт: логический день никогда не откатывается.
- **Без агента** время идёт всем запущенным программам с лимитом — даже свёрнутым. Это сделано намеренно.
